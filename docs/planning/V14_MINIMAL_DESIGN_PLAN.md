# V14 Minimal Premium 디자인 리뉴얼 기획서

> **작성**: Pomelli (기획)
> **작성일**: 2026-10-18
> **레퍼런스**: code.xr 「Dashboard V14 — Modern & Minimal UI」 (사용자 제공 스크린샷, "Rewards Program" 화면)
> **범위**: 내비게이션 쉘 + 비주얼 시스템(토큰·공용 컴포넌트) + 대시보드 재구성. 기존 라우트와 백엔드 API는 변경하지 않는다.
> **상태**: 기획 단계(미구현). 구현되면 현행 6차(Toss)를 대체하는 **7차 컨셉**이 된다.

---

## 1. 요약

레퍼런스의 핵심 문법은 세 가지다.

1. **상단 필(pill) 탭 + 아이콘 전용 레일의 2단 내비게이션** — 어두운 240px 사이드바가 없다.
2. **웜 화이트 캔버스 위 테두리 없는 큰 라운드 카드, 강조색은 오렌지 하나, 활성/주요 버튼은 검정 필**.
3. **숫자가 주인공인 히어로 카드(그라데이션) + 세그먼트 컨트롤 + 우측 정렬 값이 있는 이력 리스트**.

현행(Toss 6차)은 "다크 네이비 사이드바 + 파랑 브랜드 + 회색 캔버스"라 **색만 바꿔서는 이 인상이 나오지 않는다** — 내비게이션 쉘 구조가 달라져야 한다. 따라서 이 기획은 토큰 교체(작음)와 쉘 재구성(큼)을 분리해 단계별로 진행한다(§8).

## 4. 내비게이션 쉘 재설계

### 4.1 구조

- **상단 필 탭 = 도메인 그룹 5개** — 현행 `Sidebar.jsx`의 `NAV_GROUPS` 구성을 그대로 승계(라벨 변경 없음).
- **좌측 아이콘 레일 = 선택된 그룹의 페이지들** — 현행 아이콘(lucide) 재사용. 항목 위로 마우스를 올리면 라벨 툴팁.
- 활성 탭은 현재 라우트가 속한 그룹으로 자동 결정. 탭 클릭 시 그 그룹의 **기본 진입 페이지**로 이동.
- ⌘K 커맨드 팔레트, 상단 검색 아이콘, 테마 토글, 시스템 상태 표시는 유지(위치만 이동 — 테마 토글은 레퍼런스대로 레일 최상단).

### 4.2 그룹 ↔ 페이지 매핑 (`App.jsx` 인증 라우트 전수)

| 탭(그룹) | 기본 진입 | 레일 항목(라우트) |
|---|---|---|
| 대시보드 | `/` | 레일 없음(단일 페이지) — 레일은 해당 그룹에서 숨김 |
| 콘텐츠 | `/photos` | 사진 `/photos` · 포트폴리오 `/portfolios` · 시리즈 `/series` · 정렬 `/sort/photos`, `/sort/series` · 신고 `/reports` · 피처드 `/featured` · 콘텐츠 정책 `/content-policy` |
| 회원 | `/members` | 회원 `/members` · 작가 인증 `/verifications` |
| 운영·마케팅 | `/inquiries` | 문의 `/inquiries` · 예약 `/bookings` · 통계 `/stats` · 공지 `/notices` · 배너 `/banners` · 팝업 `/popups` |
| 설정 | `/system` | 시스템 `/system` |

- 상세 라우트(`/members/:id`, `/sort/series/:id`, `/sort/portfolios/:id`)는 부모 항목의 활성 상태를 유지한다.
- 현행 사이드바의 "정렬 관리" 아코디언은 레일에서 **아이콘 1개(정렬) → 클릭 시 사진/시리즈 선택 팝오버**로 대체한다(레일은 서브메뉴를 펼칠 폭이 없음).
- `NotFoundPage`는 현행처럼 `ProtectedRoute` 안에서 렌더링되므로 새 쉘(탭·레일)이 그대로 붙는다. 어느 탭도 활성화되지 않은 상태로 표시한다.

### 4.3 반응형

- ≤767px: 상단 탭은 가로 스크롤, 레일은 하단 고정 바(아이콘 5~6개 + "더보기")로 전환. 현행 모바일 드로어(`sidebar--mobile-open`)는 폐기.
- 768–1100px: 프로필 칩은 아바타만, 탭 라벨은 유지.

### 4.4 접근성

- 레일은 아이콘 전용이므로 모든 항목에 `aria-label`과 툴팁 필수(현행 접힘 상태 사이드바는 `title` 툴팁만 있고 `aria-label`은 없어 스크린리더 대응이 빠져 있다 — 이번에 함께 보완).
- 키보드: 탭은 `role="tablist"`, 레일은 일반 링크 리스트(`nav`). 포커스 링은 `--shadow-focus` 유지.

## 5. 대시보드 재구성 — 레퍼런스 컴포넌트 ↔ 실제 데이터

레퍼런스의 "Rewards Program" 화면 구성요소를 이 프로젝트에서 **이미 존재하는 데이터에 대응**시킨다. 신규 백엔드 API는 없다.

| 레퍼런스 요소 | Happiness Admin 대응 | 데이터 출처(기존) |
|---|---|---|
| 그라데이션 히어로 카드: 큰 숫자 + 진행바 + 흰색 버튼 | **"처리 대기" 히어로** — 큰 숫자 = 포트폴리오 심사 대기 + 신고 대기 + 작가 인증 대기 + 미읽음 문의 합계, 서브라인에 항목별 건수, 흰 버튼 "대기열 보기" | `GET /admin/stats/summary`(`pendingPortfolios`, `unreadInquiries`) + 신고·인증 각 `GET …/counts` |
| 히어로 진행바 | **보류**: "오늘 처리 완료율" 데이터가 현재 없다. 데이터 없이 장식용 바를 넣지 않는다 | — |
| "Offers for you" 3카드 (선택 카드는 오렌지 테두리, 검정 Activate 버튼) | **처리 대기 큐 3카드** — 심사 대기 포트폴리오 / 미처리 신고 / 작가 인증 대기. 건수가 가장 많은 카드에 오렌지 테두리, 버튼 "바로 처리" → 필터 적용된 목록으로 이동 | 위와 동일 |
| "Points history" 리스트(아이콘·제목·날짜·우측 +/− 값) | **최근 활동 리스트** — 아이콘 원 + 제목 + 상대 시간, 우측 값 자리에 **액션 배지**(가입/문의/심사 등). 금액 개념은 없으므로 +/− 색 구분은 쓰지 않는다 | 현행 `ActivityFeed`(문의·회원 조합) 또는 활동 로그 `GET /admin/system/activity-logs` |
| "Tier benefits" 카드(세그먼트 + 체크리스트) | **직접 대응 없음.** 세그먼트 컨트롤만 공용 컴포넌트로 추출해 통계 기간(7일/30일/…), 신고·인증 상태 필터에 적용. 체크리스트 카드는 도입하지 않는다 | — |
| (레퍼런스에 없음) 기존 KPI 7개 | 히어로 아래 **소형 KPI 스트립**으로 강등(전체 회원·사진·오늘 문의·예약 등), 이모지 → lucide | `summary` |
| (레퍼런스에 없음) 예약 캘린더·이번 주 예약·심사 대기 목록 | 유지. 카드 스타일만 V14 토큰으로 자동 반영 | 현행 |

배치(데스크톱, 12열 그리드): 히어로(8열) + 처리 대기 큐 3카드(4열 세로 스택 또는 하단 3열) → KPI 스트립 → 활동 리스트 + 예약 캘린더 → 심사 대기/최근 문의 테이블.

## 6. 디자인 토큰 변경안

**원칙: 토큰명은 유지하고 값만 교체**(6차에서 쓴 방식과 동일 — 22개 페이지 CSS가 토큰을 참조하므로 자동 반영). 새로 필요한 토큰만 추가.

| 토큰 | 현행 | 제안(추정, Phase 0에서 확정) |
|---|---|---|
| `--color-brand` | `#3182F6` | `#E8643A` |
| `--color-brand-hover` | `#1B64DA` | `#D4532B` |
| `--color-brand-light`/`-50` | `#E8F3FF` | `#FDEEE8` |
| `--color-bg` | `#F2F4F6` | `#F4F4F6` |
| `--color-text-primary` | `#191F28` | `#111111` |
| `--color-text-secondary` | `#4E5968` | `#52525B` |
| `--radius-xl` / `--radius-2xl` | 20 / 24px | 유지(카드 기본을 `xl`→`2xl`로 상향) |
| `--shadow-ring` | 2중 소프트 | 더 약하게: `0 1px 2px rgba(17,17,17,.04)` |
| **신규** `--color-ink` | — | `#111111`(활성 탭·주요 버튼) |
| **신규** `--color-ink-text` | — | `#FFFFFF` |
| **신규** `--gradient-hero` | — | `linear-gradient(135deg, #F0734A, #E8552C)` |
| **신규** `--rail-width` | — | `56px` |
| `--sidebar-*` 계열 | 다크 네이비 | **폐기**(레일은 라이트 필 컨테이너) |

- `--color-accent`(sky)는 현재 보조 액센트로 쓰이므로 유지. 오렌지가 브랜드가 되면 sky와 충돌하지 않는다.
- **주요 버튼**: `.btn-primary`(현재 브랜드 파랑 채움)를 **검정 필(`--color-ink`)**로, 오렌지 채움은 `.btn-brand`(이미 존재)로 용도 분리.
- **대비 주의**: 추정 오렌지(`#E8643A`) 위 흰 글씨 대비율은 약 3.3:1(직접 계산)로 **AA 일반 텍스트 기준 4.5:1 미달, 큰 글씨 기준 3:1 통과**. 히어로 카드의 큰 숫자·굵은 제목은 괜찮지만 작은 보조 문구는 불투명도를 올리거나 어두운 오렌지로 보정해야 한다.

**다크 테마**: 레퍼런스에 없으므로 이 기획이 정하는 가정이다 — 1차 릴리스는 **라이트 우선**. 다크는 현행 "반전하지 않고 톤만 낮춘다" 원칙으로 같은 토큰 구조에서 파생(브랜드 오렌지는 다크에서 한 단계 밝게). 다크 팔레트 확정은 별도 작업으로 분리한다.

**확장 규칙(레퍼런스에 없는 화면)**: 테이블은 보더 없는 흰 카드 + 연회색 헤더 행 + 행 구분선만 유지, 폼 입력은 연회색 채움 + 포커스 시 검정 1px 링(오렌지 아님 — 오렌지는 "상태/진행" 전용), 모달·슬라이드오버는 현행 구조 유지하되 반경·그림자만 토큰 반영, 배지는 현행 필 배지 유지.

## 7. 모션

레퍼런스의 기술 스택에는 Framer Motion이 있으나 **이 프로젝트에는 도입하지 않는다**.

- `package.json`에 `framer-motion`이 없고, 프로젝트 원칙상 근거 없이 라이브러리를 추가하지 않는다. 카드 호버 리프트는 CSS로 동일하게 구현 가능하다.
- 카드 호버: `transform: translateY(-4px)` + 그림자 한 단계 상승, `@media (hover: hover) and (pointer: fine)`로 제한, `var(--dur-normal) var(--ease-out)`. 클릭은 기존 `scale(0.97)` 유지.
- 진입 애니메이션은 현행 `IntersectionObserver` fade+slide-up 패턴 재사용. 최근 추가한 드롭다운/SlideOver 모션(`prefers-reduced-motion` 대응 포함)은 그대로 유지.
- 하드 오프셋 금지 원칙(CLAUDE.md Design Rules 6)은 **픽셀 오프셋 섀도우** 금지이며, 수직 소프트 리프트는 Toss 6차에서도 허용된 패턴이라 충돌하지 않는다.

## 9. 리스크와 가정

| 항목 | 내용 | 대응 |
|---|---|---|
| **내비게이션 경로 변경** | 모든 라우트의 접근 경로가 바뀐다(관리자 학습 비용). 가장 큰 변경 | 그룹 구성을 현행 라벨 그대로 승계해 "어느 그룹에 있는지"는 유지. Phase 2를 토큰 작업(Phase 1)과 별도 릴리스로 분리해 되돌리기 쉽게 한다 |
| **색상 추정치** | §2·§6의 hex는 눈으로 읽은 값 | Phase 0에서 샘플링 확정 |
| **가정: 5그룹 탭** | 레퍼런스는 6개 탭(Overview…Reports)이지만 본 서비스 도메인은 5그룹 | 탭 개수는 현행 `NAV_GROUPS`가 기준 |
| **가정: 라이트 우선** | 다크 레퍼런스 부재 | §6 다크 정책 — 별도 작업 |
| **히어로 합계의 의미** | 서로 다른 성격의 대기 건(심사·신고·인증·문의)을 합산하는 것이 관리자에게 의미 있는 단일 숫자인지는 검증 필요 | 합계를 크게 보이되 항목별 건수를 항상 함께 노출. 운영 피드백 후 "가장 시급한 1종만" 표시로 전환 가능 |
| **레일 항목 수** | 콘텐츠 그룹이 7개 항목(+정렬 팝오버)으로 가장 많아 56px 세로 레일에 빽빽할 수 있음 | 화면 높이 낮을 때 레일 내부 스크롤, 필요하면 "정렬"·"콘텐츠 정책"을 팝오버로 묶음 |
| **번들·성능** | 신규 라이브러리 없음 | — |
