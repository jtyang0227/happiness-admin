# AKIRA Neo-Tokyo 디자인 시스템 — 구현 기록

> **작성**: Claude Code
> **적용일**: 2026-08-23
> **범위**: `frontend/src/styles/tokens.css` 토큰 레벨 재도색(recolor) + 소수 시그니처 컴포넌트
> 디테일. 기존 4차(和ドット) 시스템의 구조(CSS 변수 단일 인터페이스, `radius:0`, 하드
> 오프셋 섀도우, 라이트/다크 보더-배경 명암 반전)는 그대로 유지하고 팔레트·타이포그래피만
> 5차로 교체했다 — 구조 재설계가 아니라 톤 전환.

## 컨셉 계보

| 세대 | 컨셉 | 상태 |
|---|---|---|
| 1차 | Cosmos × Pinterest | 레거시 |
| 2차 | Railway DNA | 레거시 |
| 3차 | Pixel Arcade | 레거시 |
| 4차 | 和ドット(와도트) — 전통 일본 색채 × 도트 게임 UI | 레거시 |
| **5차 (현재)** | **AKIRA Neo-Tokyo** — 블랙/화이트 기반 + 레드·시안 포인트 | **적용 중** |

와도트가 "패미컴 JRPG 대화창 × 전통 일본 색채"였다면, AKIRA Neo-Tokyo는 "사이버펑크
포스터 × HUD 터미널"이다. 각진 모서리·이중 프레임·하드 오프셋 섀도우 같은 **구조적
DNA는 그대로 계승**하면서, 색채·타이포그래피만 대담하게 교체했다 — 토큰 인터페이스가
이미 색상 전용으로 완전히 추상화되어 있었기 때문에 `tokens.css` 한 파일의 값 교체만으로
전 화면이 자동으로 새 톤을 입었다(컴포넌트 파일은 거의 건드리지 않음).

## 팔레트

```css
/* Brand — 전기적 포스터 레드 */
--color-brand:  #E8112D;  /* 라이트 */  /  #FF2D46 (다크)

/* Secondary accent — Neo-Tokyo 시안 네온 */
--color-accent: #0097A7;  /* 라이트 */  /  #00E5FF (다크)

/* Semantic */
--color-success: #0D9F53 / #00FF7A(다크)
--color-warning: #C98A00 / #FFD400(다크)
--color-danger:  #B0102A / #FF1744(다크)
--color-info:    #0097A7 / #00E5FF(다크)   /* = accent와 동일 계열 */

/* Neutral — 화이트/블랙 베이스 */
--color-bg:      #F4F4F4 (라이트) / #0A0A0C (다크)
--color-surface: #FFFFFF (라이트) / #131316 (다크)
--color-border:  #0A0A0A (라이트) / #FFFFFF (다크)  /* 명암 반전 그대로 계승 */

/* Sidebar — 항상 무광 블랙(라이트/다크 모드 무관) */
--color-sidebar-bg: #050505,  active-text: #FF2D46(레드)
```

와도트의 "라이트=화지+먹선, 다크=밤+크림보더" 반전 원칙을 그대로 계승했다 —
라이트 모드는 흰 배경 + 검은 보더, 다크 모드는 검은 배경 + 흰 보더로 반전된다.
브랜드 레드·시안은 두 모드 모두에서 채도를 유지해 "네온 포인트"로 튄다(다크 모드에서는
한층 밝혀 네온 발광감을 강화).

카테고리/무드 배지 색상(`--color-cat-*`, `--color-mood-*`)은 이번 재도색 범위에서
**제외**했다 — 콘텐츠 분류용 색이라 브랜드 아이덴티티와 결이 달라도 무방하고, 실제로
블랙/화이트/레드/시안 크롬 위에서도 위화감 없이 어울리는 것을 스크린샷으로 확인했다.

## 모서리 · 프레임 · 텍스처

- `radius: 0` 그대로 유지 — AKIRA 포스터의 컷아웃 실루엣과도 잘 맞는다.
- `--shadow-sm/md/lg/xl`(하드 픽셀 오프셋 버튼 섀도우), `--shadow-ring`/`--shadow-modal`
  (이중 액자 프레임)도 구조는 100% 계승, 색상만 새 보더 색을 참조하도록 자동 반영.
- **신규**: `--shadow-glow-red`, `--shadow-glow-cyan` — CTA·활성 요소 전용 네온 글로우.
  로그인 버튼 hover, 커맨드 팔레트 다이얼로그에 적용.
- **신규**: `--hazard-stripe` — 45도 블랙/레드 반복 그라디언트("경고 테이프"). 상단바
  최상단 3px 스트립(`.admin-topbar::before`)에 전 화면 공통 시그니처로 적용.
- 세이가이하(青海波) 물결무늬였던 `--dot-grid`를 CRT 스캔라인 텍스처(수평 반복 그라디언트,
  라이트 3.5%/다크 4.5% 알파)로 교체 — 배경 텍스처가 "전통 문양"에서 "HUD 노이즈"로 전환.
- `.page-title::before`의 토리이(⛩) 아이콘을 레드 타겟 리클(◉)로 교체 — Akira의 상징적
  붉은 원형 엠블럼을 재해석.

## 타이포그래피

토큰 이름(`--font-pixel`, `--font-serif`)은 하위 호환을 위해 그대로 유지하고 **값만
교체**했다 — 9개 파일에 흩어진 `var(--font-pixel)`/`var(--font-serif)` 참조를 하나도
건드리지 않고 전역 재도색이 가능했던 이유.

| 토큰 | 이전(와도트) | 현재(AKIRA) | 역할 |
|---|---|---|---|
| `--font-pixel` | DotGothic16 | **Orbitron** | KPI 숫자·브랜드 로고 전용(한글 미지원 — 기존 제약 계승) |
| `--font-serif` | Noto Serif KR | **Black Han Sans** | 페이지 타이틀 전용(한글 지원 포스터 서체) |
| `--font-sans` | Pretendard | Pretendard(변경 없음) | 본문 |
| `--font-mono` | JetBrains Mono | JetBrains Mono(변경 없음) | 코드/데이터 |

Orbitron은 기하학적 사이파이 서체로 대시보드 KPI·통계 숫자에서 "HUD 판독계기" 느낌을
주고, Black Han Sans는 한글 지원 볼드 디스플레이 서체로 포스터 타이포그래피 효과를 낸다.

## 컴포넌트 패턴

| 요소 | 처리 |
|---|---|
| 로그인 화면 | 로컬 스코프 `--lp-*` 변수를 새 팔레트로 직접 갱신(전역 토큰과 독립이므로 별도 작업 필요했음). 로고를 `Target`(리클) 아이콘으로, 타이틀을 영문 대문자+와이드 트래킹으로, CTA 버튼 hover에 레드 글로우 적용 |
| 상단바 | 최상단에 해저드 스트라이프 3px 바 추가(전 화면 공통 시그니처) |
| 사이드바 브랜드 아이콘 | `Sparkles` → `Target`(리클 모티프 통일) |
| 커맨드 팔레트 | 다이얼로그에 시안 글로우 추가 |
| StatusDot | 다이아몬드 clip-path 형태는 유지, 색상만 네온 계열로 자동 반영(`--color-status-*`) |
| 배지/버튼/테이블/모달 | 컴포넌트 코드 변경 없음 — 전부 CSS 변수 참조라 자동 반영 |

## 적용 범위

`tokens.css` + `global.css`(1곳, page-title 아이콘) + `public/index.html`(폰트 링크) 3개
파일과, 전역 토큰이 닿지 않는 로컬 스코프 예외 2곳(`LoginPage.css`의 `--lp-*`,
`LoginPage.jsx`의 로고 아이콘/타이틀 텍스트, `Sidebar.jsx`의 브랜드 아이콘)만 직접
수정했다. 그 외 **전체 20여 개 페이지·컴포넌트는 코드 변경 없이 자동으로 새 팔레트를
상속**했다 — `docs/design/WA_DOT_DESIGN_SPEC.md`의 Design Rule 1("CSS 변수만 사용,
하드코딩 금지")이 4차 롤아웃 때 전 화면에 걸쳐 엄격히 지켜진 덕분에, 5차 전환이 토큰
파일 하나로 끝났다. 라이트/다크 모드, 대시보드·회원·사진·통계·문의 등 대표 화면을
Playwright 스크린샷으로 직접 확인함.

## 알려진 예외

- 사진 카테고리 태그(`--color-cat-*`)·색채무드 배지(`--color-mood-*`)는 재도색 범위 밖 —
  콘텐츠 분류 색상이라 브랜드 팔레트와 분리 유지.
- `KpiCard`(대시보드)의 아이콘 색상은 카드별로 JSX에 하드코딩된 hex 값을 그대로 사용 —
  이번 작업 이전부터 있던 기존 패턴이며, 다양한 색 조합이 새 팔레트와도 위화감 없이
  어울려 손대지 않았다. 토큰화는 별도 과제로 남긴다.
- `frontend/login.html`(정적 프로토타입, React 앱에서 미사용)은 이번 범위에서 제외.
